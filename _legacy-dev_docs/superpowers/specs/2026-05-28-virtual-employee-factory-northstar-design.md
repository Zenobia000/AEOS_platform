# AEOS 北極星 — 虛擬員工製造工廠

> **一句話**：把任何企業的混亂知識，在數天內、近乎零邊際成本地，量產成可上線、可監控、可召回、可重組的 AI 員工——而且這條產線本身會越用越快、越用越便宜。

本文件是 AEOS 的 North-Star：把現有平台拉高到「未來工廠」的願景高度，用 Elon 第一性原理重新審視，並落到 12–18 個月可執行的 OGSM。脊椎是 Elon 的 *the machine that builds the machine*——**AEOS 真正的產品不是 AI 員工，而是量產 AI 員工的工廠本身。**

雙層時間尺度：**Part 0–5 是 10 年 moonshot，Part 6–7 是 12–18 月可執行落地，Part 8 是護欄。**

---

## Part 0 — 第一性原理重算

不從「現有 AI 員工長怎樣」出發，而是問：**一位 AI 員工的資訊本質是什麼？它的理論最低製造成本是多少？**

拆到極限，一位可上線 AI 員工 = 三樣可數位複製的東西疊起來：

```
AI 員工 = 記憶(狀態 bytes) + 身體(runtime 配置) + 技能(prompt+schema+tool 綁定)
理論邊際複製成本 ≈ 儲存 + 一次驗收算力 ≈ 趨近於 0
```

**白癡指數 (idiot index)** = 今天實際「製造」一位通過驗收 AI 員工的成本 ÷ 理論下限。今天這個數字極高，浪費不在 token，在**人工**：專家陪訓、人工標註、人工審核、逐案調 prompt。

> **核心命題**：如果複製一位 AI 員工趨近零成本，那麼價值與護城河就不在「員工」本身，而在**那條能把混亂知識可靠地量產成合格員工的產線**。
>
> 工廠即產品。AI 員工是出廠單位。

這段定錨整份文件：後面每一個設計決策，都在回答「如何把白癡指數壓低一個數量級」。

## Part 1 — 工廠願景 (10 年 Moonshot)

**工廠全景**：

```
 [原料] 混亂企業知識
    │
    ▼
╔═══════════════ AEOS 工廠 ═══════════════╗
║  鑄造 → 訓練室 → 品管閘門 → 出廠凍結    ║
║         ▲                      │         ║
║         │   標準化零件倉        │         ║
║         │  ┌─記憶模組─┐         │         ║
║         │  ├─身體 Harness┤      │         ║
║         │  └─技能 Skill─┘       │         ║
╚═════════╪══════════════════════╪═════════╝
          │                      ▼
          │              [出廠] Frozen 員工 → 部署到通道
          │                      │
          └──── 售後遙測回流 ◀────┘  (AgentOps：漂移即召回)
```

**五大未來科技支柱**（每根都是現有 AEOS 元件的「拉到極限」版）：

| # | 支柱 | 今天 (AEOS) | 10 年北極星 |
|---|------|------------|------------|
| 1 | **可抽換記憶** | L1–L4 記憶綁在員工身上 | 記憶是可拆卸、可版控、可移植的**模組**——能備份、回滾、移植到另一個身體 |
| 2 | **可重組身體** | Frozen Runtime 固定 | 同一顆腦/記憶可換不同**身體規格**（通道×模型×工具配置），像換工裝 |
| 3 | **自主沙盒鑄造** | 訓練室人陪練 + 紅隊 | 訓練室自我博弈、自動量產 Skill 候選，人只審核不陪練 |
| 4 | **全景遙測** | §12 評估 + 漂移偵測 | 出廠每一台終身被監控，漂移自動觸發**召回再訓練** |
| 5 | **生態飛輪** | Skill 商城雛形 | 遙測回流 + 零件市場 + 跨企業勞動網，越用越強 |

## Part 2 — 產線解剖 (The Production Line)

六站產線。每一站 = 現有 AEOS 元件 + 「白癡指數歸零」的進化方向。

```
站1 原料倉 → 站2 鑄造 → 站3 訓練室 → 站4 品管閘門 → 站5 出廠凍結 → 站6 售後遙測
                                                                          │
                          └──────────── 召回再訓練 ◀────────────────────┘
```

| 站 | 職責 | 今天 (AEOS) | 北極星進化 | 白癡指數殺手 |
|---|------|------------|-----------|-----------|
| **1 原料倉** | 吸收混亂知識 | 知識三分類 (Static/Policy/Dynamic) | 自動分類器：丟一坨文件，機器自動切 RAG/Rule/Tool 三路 | 消滅「人工分類知識」 |
| **2 鑄造** | 配出員工胚胎 | Bootstrap 問卷 → Employee Manifest | 從職位目錄一鍵實例化胚胎，記憶/身體/技能預載 | 消滅「人工捏 persona」 |
| **3 訓練室** | 練成可用腦 | Hermes 式 + 專家陪練 + 紅隊 | 自我博弈量產 Skill 候選，紅隊自動化，人只審不陪 | 消滅「專家逐案陪訓」 |
| **4 品管閘門** | 攔下不合格品 | 七層 Quality Gates + 驗收門檻 | 閘門全自動，人類只簽 G5；不過自動退回站3 | 消滅「人工逐項驗收」 |
| **5 出廠凍結** | 凍結後部署 | Frozen Runtime | 凍結=拍快照（記憶+身體+技能三零件版本綁定），可一鍵複製/回滾 | 消滅「重新部署的人工」 |
| **6 售後遙測** | 終身監控 | §12 AgentOps + 漂移偵測 | 漂移自動分類 → 自動生召回工單 → 餵回站3 | 消滅「人工巡檢品質」 |

**鐵律不變**：站3（會學習的腦）永遠關在沙盒，站5（出廠品）永遠 Frozen。這條「學習/生產分離」是現有 AEOS 原則 4，北極星不破壞它，只是把站3→站5 之間的人工搬運自動化。

## Part 3 — 標準化零件 (可抽換件 × 互換矩陣)

工廠的威力來自**零件標準化**（亨利福特的真正發明）。一位 AI 員工拆成三種獨立可抽換、可版控、可移植的零件：

```
記憶模組 (Memory Cartridge)   身體 (Harness)            技能 (Skill)
─────────────────────────     ─────────────────         ─────────────
L1 工作記憶                   runtime profile           prompt spec
L2 會話記憶                   通道綁定 (LINE/Web/…)     I/O schema
L2.5 摘要記憶                 模型路由 (Haiku/Opus)     allowed tools
L3 租戶知識                   工具配置                  test cases / risk
L4 營運記憶 (Phase 2)         policy 綁定               version / rollback
─────────────────────────     ─────────────────         ─────────────
可備份/回滾/移植              可換裝/重組               已是 package (現有)
```

**三條互換協議**（北極星新增、現有 AEOS 還沒有的）：

1. **記憶可移植**：把一位資深客服員工的 L3/L4 記憶模組，匯出 → 注入新胚胎，新人秒繼承經驗（現有只能重訓）。
2. **身體可重組**：同一顆腦 + 記憶，白天接 LINE 當客服身體、晚上換 API 身體做批次，像換工裝不換人。
3. **角色可重扮**：同一具身體，載不同記憶+技能，扮不同租戶的不同角色（嚴格受 tenant 隔離約束）。

**互換矩陣**：

| | 換記憶 | 換身體 | 換技能 |
|---|---|---|---|
| **效果** | 換經驗/年資 | 換通道/模型/成本檔位 | 換能力/職務 |
| **類比** | 換記憶卡 | 換工裝/換崗 | 換證照 |
| **約束** | 不可跨 tenant 移植 (PII/隔離) | 模型降階需過成本閘 | 只能載 Approved Skill |

這層把「記憶抽換 / 身體重組」從科幻變成**有版本、有約束、有審計**的工程零件——也直接餵養 Part 5 的「零件市場」生態。

## Part 4 — 垂直整合 × 五步工作法

**五步工作法套到產線**（順序神聖，不可顛倒）：

```
1 質疑需求 → 這個站/零件/流程，是真需求還是因為「人類工廠都這樣」？
2 刪除     → 能刪的站直接刪。最好的零件是不存在的零件。
3 簡化     → 刪不掉的，簡化到極限。
4 加速     → 簡化後才談加速 cycle time。
5 自動化   → 最後才自動化。(Elon 血淚教訓：先自動化會把錯誤流程固化)
```

> 反模式警告（Elon 親身踩過）：**先自動化，等於把愚蠢的流程用機器人放大。** AEOS 現有「Governance-first, DevOps-later」（原則 7）其實就是這條的同構——先把治理流程刪到對，再自動化。

**垂直整合邊界**（自製 vs 外包，用「是不是護城河 + 會不會被供應商綁架」決定）：

| 環節 | 自製/外包 | 理由 |
|---|---|---|
| 記憶層（零件規格 + 互換協議） | **自製** | 護城河核心，移植協議是別人沒有的 |
| Harness / Frozen Runtime | **自製** | 學習/生產分離是身份，不能外包 |
| 訓練室鑄造引擎 | **自製** | 量產能力 = 工廠本體 |
| 全景遙測 / AgentOps | **自製** | 原則 5「監控才是護城河」 |
| LLM 模型 | **外包但抽象化** | §13 多模型層，絕不綁單一供應商 |
| 基礎設施 (K8s/雲) | **外包** | 非護城河，延後到規模需要 |

**白癡指數歸零路徑**：每一站的人工成本逐站消滅（Part 2 最右欄），終局是「混亂知識進，合格員工出」之間的人類介入只剩**站4 的 G5 專家簽核**那一個關卡。

## Part 5 — 生態飛輪 (一引擎三放大器)

四種生態不是並列，是**一個越轉越快的飛輪 + 三個放大器**：

```
        ┌──────────── 自我強化飛輪 (引擎) ────────────┐
        │                                              │
   上線員工 → 對話遙測 → 脫敏回流 → 訓練室 → 更強員工 ─┘
        │                                              │
        ▼                                              ▼
  [放大器1 水平商城]   [放大器2 跨企業勞動網]   [放大器3 零件市場]
   Skill/MCP 第三方     AI 員工跨租戶協作        記憶/身體/技能
   造零件,平台抽成      形成網路效應             標準件自由交易
```

| 生態 | 機制 | 對映現有 AEOS | 護城河層級 (22.5) |
|---|---|---|---|
| **自我強化飛輪** | 遙測 → Compiler 3 → 再訓練 | 三 Compiler / 旁路閉環 | Layer 2 資料飛輪 |
| **水平商城** | 第三方造 Skill/MCP，平台治理+抽成 | Skill 商城 + 審核管線 | Layer 4 平台鎖定 |
| **跨企業勞動網** | AI 員工跨租戶協作（嚴格隔離下） | (新增) | 網路效應（最高） |
| **零件市場** | Part 3 三零件變可交易標準件 | (新增) | Layer 4 + 模組化生態 |

> **飛輪的 Elon 性**：Tesla 車隊跑得越多，FSD 資料越多，車就越強，賣越多。AEOS 員工上線越多，遙測越多，工廠量產的員工越強越便宜，賣越多。**這就是「越用越快、越用越便宜」的願景兌現處。**

護城河紅線（對映 22.6）：零件市場/勞動網**絕不能**退化成「賣 Agent+RAG+Workflow Designer」——賣的永遠是**治理過的、可監控可召回的零件與產線**，不是裸 agent。

## Part 6 — MVG (Minimum Viable Grand-design)

**第一條全自動產線細胞** — 對應 Tesla 用 Roadster 驗證「電動車可以令人渴望」。MVG 不是縮小版產品，是**用最聚焦的範圍去驗證整個工廠願景的核心賭注**。

**核心賭注（要被驗證的那一句）**：

> 一條產線能把「一個職位類別 + 一坨混亂知識」，在 **7 天內、人類只在 G5 簽核介入一次**，量產出通過驗收的 AI 員工；且該員工的**記憶可匯出注入新胚胎、身體可換通道**。

**範圍邊界**：

| 進 MVG | 不進 MVG (留給後續) |
|---|---|
| P0 客服職位、單一 pilot 租戶 | L4 營運記憶、跨企業勞動網 |
| L2.5 記憶模組：匯出 → 注入新胚胎 (協議1 最小版) | 第三方零件市場 |
| 雙通道身體換裝：同腦跑 LINE + Web (協議2 最小版) | 訓練室全自動自我博弈 (MVG 仍半人工) |
| 七閘門自動化，人類只簽 G5 | 跨租戶角色重扮 |
| 最小飛輪閉環：遙測→漂移→召回工單→再訓練上線 | 多租戶量產 |

**成功訊號**：

1. 製造週期 ≤ 7 天（對比真人 3 個月）
2. 人類介入 = 1 次（僅 G5）
3. 記憶匯出 → 注入新胚胎成功率 100%
4. 同腦雙通道行為一致
5. 飛輪閉環至少跑通一輪（遙測 → 召回 → 改版上線）

## Part 7 — OGSM (12–18 月落地)

**Objective**：18 個月內證明「AI 員工製造工廠」可運轉、可量產、可自我強化——把白癡指數壓低一個數量級。

| Goals (可量測) | Strategies (路徑) | Measures (KPI / Owner) |
|---|---|---|
| **G1** 製造週期 ≤ 7 天 | **S1** 七閘門自動化，只留 G5 人工 | cycle time dashboard；閘門自動通過率 ≥ 95% |
| **G2** 每員工人工介入 ≤ 1 次 | **S1+S4** 召回工單自動生成 | 人工介入點計數；誤召回率 |
| **G3** 單租戶量產 ≥ 3 職位 | **S2** L2.5 升級為可匯出/注入記憶模組 | 量產職位數；記憶移植成功率 |
| **G4** 飛輪兌現：季 FCR +X%、製造邊際成本 −Y% | **S3** 身體規格抽象層（同腦換通道/模型） | FCR 趨勢；$/出廠員工 |
| **G5** 零件互換生產驗證通過 | **S4** 最小飛輪：遙測→Compiler 3→召回→再訓練；**S5** 垂直整合自製記憶/runtime/訓練/監控，模型外包抽象化 | 互換矩陣三格通過；飛輪閉環輪次 |

每個 Measure 落到一個 Grafana/Datadog 面板 + owner，對映現有 OBS-001。X/Y 待 baseline 量測後填入。

## Part 8 — 風險與紅線

| 風險 | 護欄 | 對映現有 |
|---|---|---|
| **隱喻過度延伸** | 工廠隱喻是思考工具不是教條；別為了「像工廠」硬塞流程 | — |
| **科幻 vs 合規張力** | 記憶移植**絕不可跨 tenant**；互換協議必須在 RLS/PII 隔離內運作 | ADR-0007、ADR-0005 |
| **記憶移植破壞 Frozen 保護** | Frozen 凍結「行為」非「記憶」；移植的是事實記憶模組，不是行為改寫 | ADR-0010、原則4 |
| **自動化過早** | 五步法第5步神聖：流程沒刪對前不自動化 | 原則7 Governance-first |
| **退化成裸 agent 生意** | 零件市場/勞動網賣的永遠是「治理過、可監控可召回」的零件，不是 Agent+RAG+Workflow Designer | 22.6 紅線 |
| **誤入白領戰場** | 守住 AI 藍領 wedge | 22.8 紅線 |
