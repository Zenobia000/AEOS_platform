# The Bet — 第一性原理重算與唯一賭注

> 後面每一個決策，都在回答這份文件的問題。如果一個動作不能降低下面兩個白癡指數之一，就不做。

---

## 1. 為什麼從零重算

既有體系（whitepaper R1–R8、81 份 dev_docs）是**漸進補強**出來的——每一輪回答一個更深的決策層次（產品→服務→戰略→投資→結構→北極星）。這是**類比式推理**：「企業白皮書該有願景、護城河、投資論述、ADR、API、威脅模型……所以我們補齊」。

Elon 第一性原理拒絕這條路。不問「別的軟體公司有什麼文件」，問：

> **這家公司現在的物理現實是什麼？在這個現實下，唯一不能省的東西是什麼？**

物理現實（2026-05-28，硬數字）：

```
程式碼      = 0 行
Pilot 客戶  = 0 家
營收        = $0
團隊        = 種子前
文件        = 81 份 dev_docs + 4519 行 whitepaper + 109K agent_x.md
```

在這個現實下，唯一不能省的東西**不是文件**。是**證據**：那個核心賭注是不是真的。

---

## 2. 兩個白癡指數

白癡指數 = 實際成本 ÷ 理論下限。數字越大，浪費越多。AEOS 有兩個都爆表。

### 2.1 產品白癡指數（R8 已算對）

```
AI 員工 = 記憶(bytes) + 身體(runtime 配置) + 技能(prompt+schema+tool)
理論邊際複製成本 ≈ 儲存 + 一次驗收算力 ≈ 趨近 0
今天製造一位通過驗收 AI 員工的實際成本：極高
→ 浪費不在 token，在人工（專家陪訓、人工標註、逐案調 prompt、人工驗收）
```

這個 R8 北極星算對了，保留。**但它今天還不能被攻擊**——因為產線一行都還沒建。攻擊它的前提是先有一條跑得起來的產線。

### 2.2 文件白癡指數（R8 沒算到，這是本次重置的核心）

```
理論下限（0 客戶 0 程式碼的種子前公司，做決策與開工真正需要的文件）：
  ≈ 4–6 份
    - 賭注是什麼 + 怎麼證偽
    - 最薄切片要建什麼
    - 第一個客戶是誰
    - 燒錢跑道夠不夠

實際：81 份 dev_docs + 4519 行 whitepaper + 109K agent_x

文件白癡指數 ≈ 15–20x
```

**為什麼這是真浪費，不是「準備充分」**：

| 文件類別 | 它在解決的問題 | 這問題現在存在嗎 |
|---|---|---|
| 威脅模型 SEC-001、NFR 矩陣、OBS-001 | 「系統被攻擊 / 撐不住流量 / 觀測不到」 | ❌ 沒有系統 |
| OpenAPI API-001/002/003、ERD db-schema | 「多團隊平行實作要對齊介面」 | ❌ 沒有團隊、沒有實作 |
| 11 份 MC 契約、SAD、domain-model | 「微服務邊界要切清楚」 | ❌ 連單體都沒寫 |
| Runbook 事故/部署/備份、招募 JD、DPA/SOW | 「上線後要運維 / 要擴編 / 要簽約」 | ❌ 沒上線、沒人可招、沒客戶可簽 |
| 投資論述 05、十年護城河、生態飛輪 | 「說服 VC / 規劃十年」 | ⚠️ 部分真（募資用），但不擋開工 |

這些不是錯的文件，是**錯的時機**。它們在解決「想像中的未來企業」的問題。Linus 的話：**「這是個真問題還是臆想出來的？」** —— 大部分是臆想的。

> **關鍵洞察**：寫這些文件感覺很有生產力（「我們很嚴謹」），但它是 Elon 點名的最危險反模式——**在驗證核心賭注前，先把想像中的流程文件化，等於用文件把還沒驗證的假設『固化』成既定事實。** 之後每改一個假設，81 份文件就要 cascade。這正是 whitepaper 已經跑到 R8、改一次要同步雙版的根因。

## 3. 五步工作法套到「整個專案現狀」

R8 把五步法套到「產線」。這次套到**你現在該做什麼**。

```
1 質疑需求 → 「種子前公司需要 81 份企業文件」是真需求還是類比？
            → 類比。dumb requirement。砍。

2 刪除     → 把 81 份從決策關鍵路徑刪掉（不銷毀，退為 reference）。
            → 若刪完沒有「靠，這份其實要加回來」的衝動，代表刪得不夠。
              預測要加回的 < 10%（見 ledger 的「加回清單」）。

3 簡化     → 留下的關鍵路徑簡化到 5 份種子文件。

4 加速     → 把 13 週 sprint 計畫壓成「先用手刻一條切片跑通」，
            不先蓋自動化產線。

5 自動化   → 最後才做。七閘門自動化、訓練室自我博弈、召回工單——
            全部等「手刻切片」證明賭注成立後再說。
```

**這一步最反直覺也最重要**：你已經寫了七閘門自動化、自我博弈、零件市場的願景（R8）。Elon 血淚教訓：**先自動化 = 把愚蠢流程用機器人放大。** 你連一條人工產線都還沒跑過，現在設計自動化產線，是在自動化一個你還不知道對不對的流程。

## 4. 唯一賭注

砍到底，AEOS 整個故事縮成一句**可被證偽**的賭注：

> **一條半自動產線，能把「一個客服職位 + 一坨真實混亂知識」，在 7 天內、人類只簽核一次，量產出一位能在 LINE 上對真實客戶訊息產生『可被人類採用的草稿回覆』的 AI 員工——且該員工記憶可匯出、身體可換通道。**

拆成可獨立證偽的子賭注（按風險排序，先打最致命的）：

| # | 子賭注 | 致命性 | 怎麼證偽（最小實驗） |
|---|---|---|---|
| **B1** | 一坨真實企業 FAQ/SOP，能在數天內變成「草稿回覆採用率 ≥ X%」的可用知識 | **最致命** | 拿 1 個真客戶的真知識，手刻 ingest + RAG + draft，量真人採用率 |
| **B2** | 「人類只簽核一次」的治理閘門，在真實對話量下不會崩 | 高 | Draft Mode + Kill Switch + Audit log，跑真實 pilot 對話 |
| **B3** | 記憶可匯出注入新胚胎、身體可換通道（LINE↔Web） | 中 | 切片內預留介面，pilot 末期驗一次 |
| **B4** | 單租戶單位經濟為正（毛利 ≥ 50%） | 中（決定能不能活） | COST-MODEL 已估，pilot 量實際 token 成本驗證 |
| **B5** | 客服只是入口，平台可承接多職位（北極星） | 低（10 年後才致命） | **現在不驗。** 驗了是浪費。 |

**Linus 式裁決**：B1 是真問題，B5 是現在不存在的問題。把資源全壓 B1，是好品味。把資源分散到 B1–B5 平均用力，是垃圾。

## 5. 殺死條件（Pre-mortem，先寫下來才誠實）

Elon/Linus 都要求：**在投入前就寫下「什麼情況下我承認這是錯的」**，否則你會無限期合理化。

這個賭注**該被殺死**，如果 12 週 pilot 後出現以下任一：

```
× B1 死：真實知識 ingest 後，草稿回覆採用率 < 50%，且調 3 輪 prompt/知識結構仍上不去
  → 代表「混亂知識→可用員工」這條核心轉換不成立，整個工廠願景塌方。

× B2 死：人類為了控制 AI 出錯，實際介入次數遠超「簽核一次」（例如每 10 則要救 3 則）
  → 代表治理成本沒有比請真人低，商業模式不成立。

× B4 死：單租戶毛利長期為負，且看不到隨規模轉正的路徑
  → 代表越做越虧，不是生意。

× 簽不到客戶：8 週內連 1 個願意給真實知識 + 真實對話的 pilot 都簽不到
  → 代表市場根本不痛，或 wedge 選錯。在寫程式前就該知道。
```

**承諾**：以上任一觸發，停手、retro、要嘛 pivot wedge 要嘛收掉，**不准用「再寫一版文件 / 再補一輪願景」來逃避**。文件不能救一個被證偽的賭注。
