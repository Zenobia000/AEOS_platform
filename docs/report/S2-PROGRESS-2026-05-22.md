### 關鍵設計決策（這段最值得保留）

#### 1. Draft Mode 走「擴 status」而非「新表」
PRD §5.4 要求 AI 產 draft 但不立即送。兩個選項：
- (A) 新建 `outbound_draft` 表 → 一個 conversation 兩條 outbound 流（複雜）
- (B) 擴 `outbound_message.status` CHECK 加 `awaiting_review` / `rejected` → 同一 row 從 awaiting_review 流向 pending 或 rejected

選 (B)：OutboundProcessor partial index `WHERE status IN ('pending','retrying')` 自然隔離 awaiting_review；audit/retry/message_id 全 reuse；migration 只動 CHECK 無 backfill。成本：DraftProcessor 多 1 個 constructor param `outbound_initial_status`（預設 'pending' 向後相容）。

#### 2. Expert UI 用 monorepo lite
`web/expert/` 與 Python 後端共存：API 改 = UI 改，分 repo 反增同步成本；CI path filter 讓僅改後端不跑前端；上線時兩個 artifact 一起 build。

#### 3. expert_id 暫時走 localStorage
Phase 1 內網試用無 auth gate。S5 補 MFA + RBAC 改 server-side session。Actor_id 從 request body 帶入 audit，不影響追蹤。

#### 4. CI ci-gate aggregator
聚合 backend + web-expert 結果，repo required check 設這個就好；純文件 PR 兩 job skipped → ci-gate 仍 pass；任一失敗 → ci-gate 失敗 block merge。

#### 5. E2E smoke 不接真 LINE
用 `httpx.MockTransport` 攔 LINE Push。原因：LINE sandbox channel 還沒註冊 / E2E 在 CI 跑不依賴外網。真實 LINE 整合留給 S6 Pilot Hardening。
