# The Bet — 第一性原理與唯一賭注

> 後面每一個決策，都在回答這份文件。一個動作若不能降低白癡指數、不能逼近驗證這個賭注，就不做。

---

## 1. 第一性原理

不問「別的軟體公司有什麼」，問：**這家公司現在的物理現實是什麼？在這現實下唯一不能省的是什麼？**

物理現實：**0 行程式碼、0 個 pilot 客戶、$0 營收、種子前團隊。**

在這現實下，唯一不能省的不是規格文件，是**證據**——那個核心賭注是不是真的。

## 2. 產品白癡指數

白癡指數 = 實際成本 ÷ 理論下限。數字越大、浪費越多。

```
AI 員工 = 記憶(bytes) + 身體(runtime 配置) + 技能(prompt+schema+tool)
理論邊際複製成本 ≈ 儲存 + 一次驗收算力 ≈ 趨近 0
今天製造一位通過驗收 AI 員工的實際成本：極高
→ 浪費不在 token，在人工：專家陪訓、人工標註、逐案調 prompt、人工驗收
```

**核心命題**：複製趨近零成本時，護城河不在「員工」，在**那條把混亂知識量產成合格員工的產線**。要攻擊這個白癡指數，前提是先有一條跑得起來的產線——所以先有切片，再談自動化。

## 3. 唯一賭注

砍到底，整個故事縮成一句**可被證偽**的賭注：

> **一條半自動產線，能把「一個客服職位 + 一坨真實混亂知識」，在 7 天內、人類只簽核一次，量產出一位能在 LINE 上對真實客戶訊息產生「可被人類採用的草稿回覆」的 AI 員工——且該員工記憶可匯出、身體可換通道。**

拆成可獨立證偽的子賭注（按風險排序，先打最致命的）：

| # | 子賭注 | 致命性 | 最小證偽實驗 |
|---|---|---|---|
| **B1** | 真實 FAQ/SOP 能在數天內變成「草稿採用率 ≥ X%」的可用知識 | **最致命** | 1 個真客戶知識，手刻 ingest+RAG+draft，量真人採用率 |
| **B2** | 「人類只簽核一次」的治理閘門，真實對話量下不崩 | 高 | Draft Mode + Kill Switch + Audit，跑真實 pilot 對話 |
| **B3** | 記憶可匯出注入、身體可換通道（LINE↔Web） | 中 | 切片預留介面，pilot 末驗一次 |
| **B4** | 單租戶單位經濟為正（毛利 ≥ 50%） | 中（決定能否活） | pilot 量實際 token 成本驗證 |
| **B5** | 客服只是入口，平台可承接多職位 | 低（10 年後才致命） | **現在不驗，驗了是浪費** |

**裁決**：資源全壓 B1。把資源平均分散到 B1–B5 是垃圾；全壓最致命的 B1 才是好品味。

## 4. 殺死條件（Pre-mortem）

在投入前就寫下「什麼情況承認錯」，否則會無限期合理化。12 週 pilot 後，任一為真即 Kill / Pivot：

```
× B1 死：真實知識 ingest 後草稿採用率 < 50%，且調 3 輪 prompt/知識結構仍上不去
         → 「混亂知識 → 可用員工」核心轉換不成立，工廠願景塌方
× B2 死：人類實際介入次數遠超「簽核一次」（如每 10 則救 3 則）
         → 治理成本沒比真人低，商業模式不成立
× B4 死：單租戶毛利長期為負且無轉正路徑 → 不是生意
× 市場死：8 週內連 1 個願給真知識+真對話的 pilot 都簽不到 → 不痛或 wedge 錯
```

**承諾**：任一觸發即停手、retro、pivot 或收掉，**不准用「再寫一版文件 / 再補一輪願景」逃避**。文件不能救一個被證偽的賭注。
